# Getting Started

How to build and run the template on an Android emulator and an iOS
simulator. The project uses **Expo with Continuous Native Generation**: the
`android/` and `ios/` projects are generated by `expo prebuild` and are
**gitignored — never hand-edit or commit them**. There is no EAS Build and no
Expo Go dependency; the app runs as a **dev-client** debug build produced by
Gradle / Xcode.

## Prerequisites

| All platforms | Android | iOS (macOS only) |
|---------------|---------|------------------|
| Node 22 LTS | Android Studio (SDK 35+, an AVD/emulator) | Xcode 26+ |
| Yarn 1 (classic) | JDK 17 | CocoaPods (`sudo gem install cocoapods` or via Homebrew) |

> Expo SDK 57 / React Native 0.86 need **Swift 6.2 (Xcode 26+)** — the
> `ExpoModulesJSI` xcframework build fails on the Swift 6.1 that ships with
> Xcode 16.4. CI pins **Xcode 26.2**; see [AzurePipelines.md](AzurePipelines.md).

## First run

```sh
yarn install
```

### Android (Windows, macOS, or Linux)

```sh
# Start an Android emulator (or connect a device), then:
yarn android          # expo run:android
```

`expo run:android` performs the prebuild automatically when `android/` is
missing, builds the debug APK with Gradle, installs it on the
emulator/device, and starts the Metro dev server.

To run the steps separately:

```sh
npx expo prebuild --platform android   # (re)generate android/
cd android && ./gradlew assembleDebug  # build the debug APK
```

### iOS (macOS only)

```sh
# Start an iOS simulator (or connect a device), then:
yarn ios              # expo run:ios
```

`expo run:ios` prebuilds `ios/` (including `pod install`), builds the debug
app with Xcode, installs it on the simulator, and starts Metro.

To run the steps separately:

```sh
npx expo prebuild --platform ios       # (re)generate ios/ + pod install
xcodebuild build \
  -workspace ios/ReactNativeAppTemplate.xcworkspace \
  -scheme ReactNativeAppTemplate \
  -configuration Debug -sdk iphonesimulator
```

## Day-to-day development

Once a dev-client build is installed, only JavaScript changes are needed most
of the time — start Metro alone with:

```sh
yarn start            # expo start
```

Rebuild the native app (rerun `yarn android` / `yarn ios`) only when native
configuration changes: a new native dependency, a config-plugin change, or an
`app.config.ts` change that affects the native projects.

If the generated projects get into a bad state, delete and regenerate them:

```sh
npx expo prebuild --clean
```

## Verify loop

```sh
yarn typecheck && yarn lint && yarn test
```

This must pass before proposing any change (see
[CLAUDE.md](../CLAUDE.md)). It is the same sequence CI runs on every PR
([AzurePipelines.md](AzurePipelines.md)).
